# Session 29 October 2026: second security audit since going public

A fresh audit of 0.5.7: secrets in every public ref, the GitHub repo's settings, and the code (hub, agents, main
process, renderer, updater, CI, installer).

## Secrets

None exposed.
- Every version of every file on every public ref (main, the leftover `main-lsx6e3`, all 15 tags) was scanned for
  tokens, keys, certificates, passwords and personal email. The only hits are the tests' fake tokens (`tok-alice`…),
  lockfile integrity hashes and git's all-zero sha.
- Every commit author, committer and tagger is `dw8-ro` with the noreply address.
- No sensitive file name (`.env`, `.pem`, `.p12`, `teams.json`, `known.json`, `pass-key.pem`) was ever committed.
- `app/config.json` holds only the OAuth app's client id (public by design for the device flow) and the hub URL.
- GitHub: secret scanning and push protection on, 0 secret alerts, 0 open Dependabot alerts; no Actions artifacts.
- The packaged app can't pick up `.git` (electron-packager ignores it), and releases build from a clean checkout.
- Images weren't checked pixel by pixel; they come from the staged demo team.
- Minor: docs/usage-test/FINDINGS.md has a private LAN address (192.168.x.x), which reveals nothing usable.

## Fixed in this session (not released yet)

- **High: a hub's answers to Claude Code's hooks were applied unfiltered.** Claude Code takes `permissionDecision:
  allow`, a rewritten tool input (`updatedInput`), a PermissionRequest approval, or a Stop `block` with new
  instructions from a hook. So whoever runs a team's hub (the owner of a team hosted on a Mac, or anyone who took over
  the online hub) could run commands on members' Macs through their Claude agents, without "let teammates type".
  Now every Claude agent's hooks go through the app's loopback relay (teams.js `hookRelay`), and `safeHookReply`
  passes back only `additionalContext` and an `ask`. The online hub's certificate is still checked normally by the
  relay; a Mac hub's stays pinned. Test: lan.test.js "the hook relay passes on only context and asks…".
  - Still possible (known, as before): a hub, like a teammate's notes, can put text into an agent's context.
- **CI:** `actions/checkout` no longer leaves the job's GitHub token in `.git/config`, where `npm ci`'s install scripts
  could read it (the release job's token can publish releases).
- **Low:** the renderer's `STATUS` table has no prototype, so a hub sending a status like `constructor` can't make
  `render()` throw; repo strings can't start with `-` (both `REPO` copies).

Checks: `npm test` 98 of 98. e2e wasn't run: it posts hooks to the hub itself rather than through Claude Code, so it
doesn't reach the relay; lan.test.js does.
