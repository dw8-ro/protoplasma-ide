## Finding 1 (low): merge-tree checks pile up unreachable loose objects in the shared clone
src/lane.js mainConflicts/branchConflicts/mergeTree (~lines 118-155). Every recompute (HEAD, main or a branch moves) runs `git merge-tree --write-tree` for up to 10 branches per folder; clean merges write objects too. Repro (work/find-lane-agents/mt): 30 runs -> 90 unreachable loose objects in a tiny repo; deep paths write more trees. All session worktrees share the clone's object store. gc only prunes unreachable loose objects older than 2 weeks (gc.pruneExpire), so past gc.auto (6700) `gc --auto` can't get below the limit, writes .git/gc.log "too many unreachable loose objects; run git prune" and every later auto-gc in that clone (the person's own commit/fetch) prints that warning for a day at a time. AGENTS.md:334 says git's gc clears them, which holds only after 2 weeks. Not on main. Fix: run merge-tree with GIT_OBJECT_DIRECTORY pointed at a temp dir plus GIT_ALTERNATE_OBJECT_DIRECTORIES=<repo objects> (and delete it after), or use `merge-tree --write-tree` only when HEAD/main pair changed AND limit to branches whose files intersect this checkout's changed files.

## Finding 2 (medium): a squash- or rebase-merged session branch is reported as a conflict forever, and fed into agents' prompts
src/lane.js branchConflicts (~line 140): "A branch with nothing main lacks (merged, or not started) is left out" is tested with `rev-list --count main..<branch>`, which is >0 after a squash or rebase merge (the branch's own commits never become ancestors of main). merge-tree HEAD <branch> then reports a conflict whenever this checkout (through main's squash commit plus later edits) changed the same lines again. Repro work/find-lane-agents/sq: session/old squash-merged into main, session/mine edits the same line later: own=1, merge-tree lists f. hub.js:393 puts the first 3 branchConflicts into every UserPromptSubmit context ("Agree with whoever works there who changes those first"), and the UI shows it, for a session that is finished. Lasts until the branch is deleted on GitHub or 10 newer session branches push it out (MAX_BRANCHES). Not on main (new). Fix: also skip a branch whose changes main already has, e.g. `git merge-tree --write-tree <main> <branch>` gives main's own tree (or `git cherry <main> <branch>` shows only '-'), or skip branches of sessions the hub marks done.

## Finding 3 (low): OpenCode plugin treats a subagent's session like the main one
src/opencode-plugin.mjs `event` / `chat.message`: OpenCode's `task` tool runs a subagent in a child session; its prompt goes through chat.message and its finish emits session.idle with the child's sessionID. The plugin ignores sessionID for events, so a subagent finishing posts Stop (lane shows Idle while the parent turn keeps working, until its next tool hook) and a subagent's prompt (written by the model) is posted as UserPromptSubmit, which the hub keeps as the lane's last prompt (shown to teammates, used by Continue). Medium confidence (from OpenCode 1.x design; plugin header says never run against a live model). Fix: note child sessions (session.created with info.parentID) and skip chat.message/session.idle/permission events for them.
