# verify-lane-agents

## lane-agents-1: confirmed, medium
Repro work/verify-lane-agents/sq (isolated config, git 2.56.1): session/old (2 commits) squash-merged into main, session/mine changes the same line again. rev-list --count main..session/old = 2; merge-tree HEAD session/old lists `f` (conflict). Hub (hub.js ~393) injects up to 3 branchConflicts into every UserPromptSubmit context and doesn't filter done sessions. Worse than stated: fetchGit runs `git fetch --quiet` without --prune, so deleting the remote branch on GitHub doesn't clear the local origin/session/old ref either; only MAX_BRANCHES push-out or a manual prune. New on the branch (5e896c4 lane.js has no merge-tree).
Fix note: `git cherry` does NOT work for a multi-commit squash (both commits show '+' in the repro). `merge-tree --write-tree <main> <branch>` == `<main>^{tree}` does work here (identical ids). Add a squash case to test/conflicts.test.js.

## lane-agents-2: confirmed, low
Repro: git 2.56.1, empty config: with ~4000 young unreachable loose objects, `gc --auto` (foreground) packs nothing useful and prints "There are too many unreachable loose objects; run 'git prune'"; detached gc writes that to gc.log and later commits/fetches repeat it. Rate caveat: identical merges write no new objects (30 identical runs added 2), and lane.js caches per (HEAD,branch,main) pair, so growth is only per distinct merge result (~a few objects each: conflict-marker blobs + trees along the paths). Reaching 6700 in under 2 weeks needs a busy team (~500 new merge results/day per clone). Low is right. Temp GIT_OBJECT_DIRECTORY + GIT_ALTERNATE_OBJECT_DIRECTORIES is a correct fix.

## lane-agents-3: confirmed, low
Read the JS embedded in the installed OpenCode 1.19.5 binary (strings only, not run; the version the plugin targets). TaskTool creates a child session `r.create({parentID:u.sessionID, title: ... (@agent subagent)})`, then `promptOps.prompt({sessionID:T.id, parts: resolvePromptParts(p.prompt)})`. That goes through the same prompt path that runs `trigger("chat.message",{sessionID:d.sessionID,...})` with non-synthetic text parts. `SessionStatus.set` publishes `session.idle` for any sessionID that goes idle, the child's included. The plugin's event handler (opencode-plugin.mjs:43-48) and chat.message (29-33) never look at sessionID. So the subagent's prompt reaches the hub as UserPromptSubmit, and the child's idle reaches it as Stop (hub.js:642 sets the lane to idle) while the parent still works, until the parent's next PreToolUse. Only a status/prompt display error, so low. The suggested fix (note child ids from session.created where info.parentID is set, then skip their chat.message, idle and permission events) is right. Keep permission events for child sessions, though: a subagent's permission prompt still needs the person, so skipping it would hide a real "needs you".
