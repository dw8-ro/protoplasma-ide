# verify-renderer-solo

## renderer-solo-1: confirmed, medium
deleteSession (renderer.js 1027-1039) offers removing <clone>@<key> whenever the record has a stored source; moveSession (1285-1299) keeps the old record (done) and its sourceKey in the source team and copies the source to the target, so both records map to the same folder. The 'running' guard (sessionMenu 1268) only sees the current team's hubLanes; main.js sessions:removeFolder (229-233) has no lanes check; workspace.js removeSessionWorktree (81-91) runs plain `git worktree remove`, which refuses only modified/untracked files, not a running process; code.js forgetFolder (180) drops parked unsaved buffers. The same-folder clash existed on main (same session name in two teams), but move makes it the normal path. Fix: main refuses while any lane cwd is inside dir; renderer also skips forgetFolder/offer when parked buffers exist or say the folder may be used elsewhere.

## renderer-solo-2: confirmed, low (reported medium)
renderTeamPane solo text (1929-1935) promises "Nobody else sees its sessions" and offers "Invite them here. Your sessions stay where they are."; #inviteBtn sets #inviteTeam to currentTeam.name ("<login>'s team"), #inviteForm calls proto.invite with no isSolo branch, main teams:invite has no warning. After the invite the space is an ordinary team and broadcastState sends all sessions, notes and stopped-agent screens. New in 0.7.0. Lowered to low: the recipient is someone the person deliberately invited "here"; the defect is missing disclosure (and the dialog naming a team the user never saw), not an outsider getting in. Fix: a confirm naming what becomes visible when isSolo(currentTeam), and show "Just me" in the dialog.

## renderer-solo-3: confirmed, low (reported medium)
moveSession 1290-1291 calls saveSession(target, {name:key, task}) then renameSession when key !== name. hub.js 847-852: findSession match joins (ensureSession) and an owner or creator overwrites task; renameSession then renames the matched session (owner) or 403s after the join, leaving the source not marked done. Joining a same-named session is the documented "create joins" rule, and the shared session/<slug> branch would be shared anyway (folder and branch are named by slug, not team; that was true on main), so the real harm is the owner's goal overwrite and the rename of a teammate's session. Needs a name collision in the target team, so low. Fix: detect a match before saving (hub 409 on a `move` flag, or check the target's sessions) and ask for another name.

## renderer-solo-4: confirmed, low
renderer.js 369-370: setInterval 10 min plus addEventListener('focus', checkInvites), no throttle or in-flight guard; checkInvites -> proto.teams -> main teams:list -> teams.js listTeams 303-324 always includes the online hub (GET /teams via hubApi), calls register(), and browses Bonjour when findNearby is on. Only while isSolo(currentTeam). The focus check is deliberate (comment 352-354: "where someone told they were invited looks first"), but the "rarely wakes the online hub" claim does not hold with it. Cost: the hub stays awake for solo users who switch windows often, plus a GitHub /user lookup per 2-minute identify cache miss. Fix: a short throttle (about 1-2 min, not 10, or the told-you-were-invited case is lost) plus one request in flight.

No try/catch around render() in onmessage (533-549).
